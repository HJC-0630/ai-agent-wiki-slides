# 05. 實戰案例：從 LLM Wiki 自動生成教學 HTML 簡報

## 1. 系統目標
以結構化的 `wiki/` Markdown 知識庫為唯一事實來源，透過結合 **Planning** 與 **Reflection** 的狀態圖工作流，自動生成一份可供初學者瀏覽的單頁式教學 HTML 簡報。

## 2. 完整節點運作管線
1. **Node 1 - Ingest & Schema Discussion（架構討論與知識入庫）**：先與人類討論確定 5 篇知識條目大綱，再將原始技術文件彙整為標準 Markdown 檔案。
2. **Node 2 - Query Wiki（知識檢索）**：根據每頁投影片的教學目標，精準讀取對應的 `wiki/*.md` 條目內容。
3. **Node 3 - Draft Slide JSON（講稿草稿生成）**：依據 Planning 大綱，產出包含 `title`、`bullet_points`、`analogy`（生活比喻）與 `wiki_source` 的結構化資料。
4. **Node 4 - Critic Gate（事實驗證與易讀性檢查）**：檢查草稿是否偏離 Wiki、字數是否超過 120 字、是否缺少來源標註。若不通過則將修改建議寫入 State 並退回 Node 3。
5. **Node 5 - HTML Compiler（前端網頁編譯）**：確認講稿通過驗證後，將結構化資料填入 Tailwind CSS 投影片模板，綁定鍵盤左右鍵切換事件，輸出最終 `index.html`。

## 3. 關鍵成效對比
- **未加入前置檢查前**：約 50% 的生成結果會出現單頁文字過多導致網頁捲動破版，或遺漏 Wiki 來源標註。
- **加入前置 Reflection 迴圈後**：所有文字缺陷皆在 Node 3～4 的輕量迴圈中被攔截修正，最終 HTML 編譯一次通過率達 100%。
