# 02. Planning（規劃模式）：任務拆解與推理行動

## 1. 為什麼需要 Planning？
當使用者提出一個龐大且模糊的目標（例如：「幫我做一份給初學者看的 AI Agent 教學簡報」）時，如果直接要求 LLM 一次生成最終網頁，模型往往會因為注意力分散而遺漏重點或結構混亂。**Planning 模式**讓 AI 先扮演「專案經理」，在動手執行前先制定步驟清單。

## 2. 核心技術機制
### (1) 任務拆解（Task Decomposition）
將複雜的單一大目標，拆解為數個彼此獨立、有先後順序的子任務（Sub-tasks）。
- **範例**：「製作教學簡報」→ 拆解為 `1. 確定目標受眾` → `2. 檢索知識庫條目` → `3. 擬定每頁大綱` → `4. 撰寫白話講稿` → `5. 編譯 HTML 網頁`。

### (2) Chain-of-Thought（思維鏈, CoT）
透過「讓我們一步一步思考（Let's think step by step）」的提示策略，強迫模型在給出最終答案前，先輸出中間的邏輯推演過程，大幅提升複雜任務的準確率。

### (3) ReAct 框架（Reason + Act）
結合「推理（Reasoning）」與「行動（Acting）」的動態規劃模式：
1. **Thought（思考）**：分析目前還缺少什麼資訊。
2. **Action（行動）**：決定呼叫哪個工具（例如查詢 `wiki/03_reflection.md`）。
3. **Observation（觀察）**：讀取工具回傳的資料，再決定下一步是繼續查資料還是開始寫作。
