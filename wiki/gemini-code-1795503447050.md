# 03. Reflection（反思模式）：自我審查與迭代修正

## 1. 核心概念
人類在寫報告或做簡報時，很少第一遍就寫出完美定稿，而是透過「寫初稿 → 自己重讀檢查 → 修改潤飾」來提升品質。**Reflection 模式**正是把這個迭代過程自動化，讓 LLM 在產出結果後，針對特定標準進行自我批判與重寫。

## 2. 雙角色迭代架構（Actor-Critic Loop）
在實作 Reflection 時，通常會將系統拆分為兩個邏輯角色（可由同一個模型切換不同 System Prompt 扮演）：
1. **Actor（創作者角色）**：負責根據知識庫內容生成第一版教學草稿（Draft v1）。
2. **Critic（審查者角色）**：負責扮演嚴格的編輯或初學者代表，根據預設檢核表（Checklist）逐項打分並指出具體缺陷。
3. **Refiner（修正階段）**：將 Critic 產出的修改建議（Feedback）連同初稿一起交回給 Actor，產出改進後的版本（Draft v2）。

## 3. 常見的審查維度（Checklist 設計）
- **事實一致性（Grounding）**：所有數據與定義是否皆出自 LLM Wiki，沒有自行腦補？
- **教學易讀性（Readability）**：是否避免堆砌艱澀術語，並附帶生活化比喻？
- **版面限制（Formatting）**：單頁投影片是否控制在 3～4 個要點、總字數 120 字以內？
